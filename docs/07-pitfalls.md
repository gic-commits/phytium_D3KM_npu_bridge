# 踩坑速查（按症状索引）

> 每条都是真机上花掉数小时才定位的；**多数会伪装成"硬件问题"**。排障时直接搜症状。

## A. 症状 → 第一嫌疑 → 动作

| 症状 | 第一嫌疑 | 动作 |
|---|---|---|
| **偶发失败 / 每次行为不同，但硬件计数完全相同** | 自己桥接里的**未初始化值 / UB** | 查所有 `copy_from_user` 之前的字段使用；`-Wmaybe-uninitialized`；`memset` 结构体 |
| **小模型一直正常、大一点的模型挂死** | 完成判定/看门狗里的**尺寸白名单** | 完成判定禁止按尺寸/页号/名字过滤；大缓冲也要纳入（头尾采样） |
| **"流取完（`CMDREQ_RD_WORD` = 总字数）、无 fault、不发完成事件"** | 完成判定漏判 ⇒ 没推响应 | 读自己的看门狗代码，列出它覆盖哪些缓冲 |
| **同进程第 1 次快、第 2 次起固定 ~40 s** | `msleep(1)` 实际 ≈8 ms，把**循环次数当毫秒** | 用 `ktime` 真实截止；模块自报耗时 vs dmesg 墙上时间戳不一致即确诊 |
| **同一个输入重复推理永远"不完成"** | 完成判据用"输出 CRC 变化"（结果恒定 ⇒ CRC 不变）| 完成信号改用 **IRQ 响应 + 累计计数** |
| **完成判定时好时坏** | 用了会被并发消费者改变的量（响应列表长度）| 一律用**累计/单调量** |
| **同一模型连跑 N 次全绿，换模型必挂** | 库按可重复标识（如 `sid`）匹配任务 | 见 `docs/04`：抓两次请求的该字段，别从引擎/时序起步 |
| **"引擎写了、App 看不到（输出恰好全 0）"** | 厂商运行时漏了"设备页→App 缓冲"的搬运/激活 | 用页级直读工具确认设备页有数据；落点选**用户态 compat**（写 `out_mats[i].data`）|
| **框对、分数怪、误检很多** | 交付的是 **pre-softmax logits**，激活缺失 | 施加正确激活（yunet = 2 类 softmax）后重新解码 |
| **取指字数打满就以为执行完成** | 预取/取指 ≠ 执行 | 输出缓冲前后 CRC + 同输入跑两遍 |
| **"没有完成事件"** | 内核 IRQ top-half **先读到并清掉了**事件 | IRQ 里加日志；**诊断代码只读不清**事件寄存器 |
| **桥接的 poll 永远读到事件位 0** | 与 top-half 竞态（你先清，top-half `IRQ_NONE`，线程不跑）| 诊断路径绝不写 `EVENT_CLEAR` |
| **对端库挂死、但库零报错** | 响应被**静默丢弃/投递错位** | 挂死≠超时失败；抓响应字节与匹配键 |
| **`stream_size == 0` 时引擎不动且无报错** | 官方 `(0/32 - 1)` 在 u32 下溢 ⇒ 控制字 `0xFFFFFFFF` | 桥接**必须拒绝 `stream_size==0` 并报错**；单位（字节 vs 字）用 CONTROL 低 8 位反解 |
| **`ADDR_USED` 被当成"配了几块缓冲"** | `|=1<<idx` 会把重复 idx 静默折叠 | 并排 `all/fd[]/idx[]` 复算，别用 `ADDR_USED` 反推 |
| **输入缓冲没被编程进 `ADDR*`** | 官方 `if (!fd[i]) continue;` 把"句柄 0"当空槽 | 空槽判据改 `idx[i]==0 && bufsizes[i]==0` |
| **服务起来了但所有请求秒失败、worker 从未启动** | 队列超时判据把**序号**当时间戳 | `enq=now_ms()` 与 `seq=++g_seq` **分字段** |
| **服务随机整体失去响应（所有客户端一起卡）** | 向挂死 worker 写大数据阻塞了工作线程 | 管道读写都要 `poll` + 超时；超时即杀 worker |
| **worker 报告"响应格式错"** | 协议通道挂在 fd1 上，被**库的 stdout 噪音**污染 | 协议 fd `dup` 到高位，**0/1 让给库** |
| **新旧 worker 同时存活、抢设备** | 设了 `SIGCHLD=SIG_IGN` ⇒ `waitpid` 返回 `ECHILD` 误判"已停" | 不设 `SIGCHLD=SIG_IGN`，自己回收 |
| **`pkill -f <模式>` 把自己的 ssh 会话杀了** | `-f` 匹配到自己的命令行 | 一律 `pkill -x <进程名>` |
| **远程长任务被切断、留下半截结果+残留进程** | ssh 前台上限（600 s，实测常 ~420 s）；ssh 断开带走远端脚本 | `nohup setsid bash test.sh > out 2>&1 </dev/null &` + 轮询结果文件 |
| **跨进程读设备缓冲总是 `-19 ENODEV`** | 桥接按**会话/文件实例**校验分配 | 只能在持有该会话的进程内读（或桥接侧加 dump）|
| **`mmap` 后内容为空就断定"内核没装载"** | 弱启发式（该缓冲可能根本不该由 host 读）| 先用缓冲**名字** + 尺寸交叉确认"这是我找的那块" |
| **官方头文件字段偏移"看起来对"却解出全 0** | 厂商库的结构体版本与官方头**有 12 字节差异** | 用真机描述符 hexdump 反解；判据是"**解出来的值是否讲得通**" |
| **厂商 demo 起不来 ⇒ 以为引擎/模型不支持** | demo 缺依赖（缺某个 `.so` 就根本起不到 start）| 换**自建最小运行器**（只依赖 core/imgproc/imgcodecs）复测 |
| **"某模型缺协议常量/代别不支持"** | 容器头部字确实分代，但**不是**卡住的原因 | 代别指纹只能当线索；仍须回到"提交→取指→完成"链上验证 |
| **读寄存器得到整块全 0（连常量都 0）** | 事后快照 = 电源态/超时清理后的读数 | 改**运行中轮询**（0.2 s 一次少量关键寄存器）|

| **脚本输出戛然而止、退出码却是 0** | `pkill` 无匹配返回 1，配 `set -e` 把脚本当场打死 | 清理类命令一律 `pkill -x … \|\| true` |
| **脚本跑到 `wait` 就再也不动了** | `wait` 会连 **nohup 起的服务**一起等（服务不退） | 用显式 PID `wait $P1 $P2`，或先停服务再 `wait` |
| **`dmesg \| grep -c oops` 报出 3 条** | 误匹配 systemd 加载的 **`ramoops`** 模块 | 判据写成 `\| grep -v ramoops`（或用 `grep -E 'oops|BUG:'` 后再排除） |
| **重启后推理"成功"但没有真实结果** | 驱动**开机自动以 `sim=1` 加载**（模拟模式，不碰硬件） | `echo 0 > /sys/module/phytium_npu/parameters/vha_sim_mode`（**运行时可写，无需 rmmod**）；验收前先确认 `sim=0` |
| **systemd 起的服务，命令行客户端连不上** | 客户端默认只连 `/tmp/npu.sock`，而 unit 用的是 `/run/npu/npu.sock` | 客户端支持 `NPU_SOCK`（解析顺序：显式参数 > `NPU_SOCK` > 默认） |

## B. 通用纪律（比单个 bug 更值钱）

1. **每个新功能：模块参数默认关 + 一路打印判定结果 + 一键回退**（`echo 0 > /sys/.../param`）。
2. **改动可回退写进流程**：改前存源码 tar + 旧 `.ko`；只改一个文件并记录行数变化；报告里给逐字可执行的回退命令。
3. **改内核模块先"只编译不装载"**（在 `/dev/shm` 副本里 `make`），受"rmmod 前先问用户"约束时特别有用。
4. **验收必须含跨模型轮换 + 中断自愈**两类用例；只跑同一模型会掩盖一批缺陷。
5. **把"结论"和"未验证假设"分开写**；推翻自己上一版结论时，**在原处标注更正并指向新文档**。
6. **设备会被移动/休眠**：每个阶段结束就假设"下一条命令可能连不上"，能离线算的先算完（容器解析、CRC 对照、反汇编）。
7. **加速器单实例**：同一时刻只允许一个进程占用；联调前先确认没有残留进程（否则会把"互抢"误判成模型问题）。
