## 三、★★★★★★★ 借壳可行性速测（`bk_probe.py` / `bk_cap.py`）

对 5 个**最小算子形态**分别建 ORT session，记录 **EP 认领数** 与 **能否执行**：

| 形态 | 图内容 | NPU 认领 | 执行 | 备注 |
|---|---|---|---|---|
| m1 | 1×1 Conv | **1/1** | ✅ OK | 基线 |
| m2 | **MatMul 原样** | **1/1** | ✅ OK | ★ 单独 MatMul **能被认领** |
| m3 | **MatMul → Transpose→Unsqueeze→Conv1×1→Squeeze** | **2/4** | ✅ OK | ★★ **借壳通路成立** |
| m4 | depthwise Conv `kernel=[11,1] group=512 pads=[5,0,5,0]` | 1/1 | ✅（但报错） | 输出绑定 `409600 < 2396160`（**5.85×**） |
| m5 | 普通 Conv `kernel=[11,1]` | 1/1 | ✅（但报错） | 输出绑定 `6400 < 37440`（**5.85×**） |

### 三条新结论
1. **"NPU 只支持 CNN" 是对【离线编译器】成立；对【ORT EP 的算子认领】并不完全成立**
   —— 单个 `MatMul` 实测能被 EP 认领。
2. **`MatMul → 1×1 Conv` 改造后被认领且能执行** ⇒ **"借壳"通路验证成立。**
3. **整模型只认 1/3803 的真因 = 分区（partition）编译失败（FRC），不是算子逐个不支持。**
   单个算子都行，**成片组起来编译不过**。
4. **`11×1` 卷积（FSMN 形态）触发 5.85× 的输出缓冲口径错** —— 与 SenseVoice 的
   `417792 → 2445312` **完全同源**，是**独立于本模型**的形态缺陷。

## 四、由此得到的"借壳"作战方案

**目标**：把 NPU 认领数从 1 → 数百。

1. **主体改造**：`MatMul(421) → 1×1 Conv`（已验证可行）。注意保持权重常量、形状静态。
2. **规避形态缺陷**：`11×1` 的 70 个 FSMN 卷积 → 写进 `unspported_nodes_file` 交 CPU
   （它们只占 70/4084，且是唯一触发 5.85× 错的形态）。
3. **降低"分区编译失败"概率**：**让 NPU 认领的子图小而成片**（若干 1×1 Conv + 激活），
   避免把大量异构算子塞进同一分区 —— 这是 FRC 的主要来源。
4. **验证口径**：每轮只改一处，用 `GetCapability` 的 `number of nodes supported by PHYNPU`
   与执行成功率为唯一判据（**不靠推测**）。
